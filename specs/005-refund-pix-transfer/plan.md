# Implementation Plan: Refund via PIX Transfer

**Branch**: `[###-refund-pix-transfer]` | **Date**: 2026-05-17 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/005-refund-pix-transfer/spec.md`

## Summary

Implement a background consumer that, after the penalty calculation for a cancelled order, initiates a PIX transfer from Tilt's internal wallet to the customer's WalletId (random UUID key). The flow validates the WalletId, skips zero‑amount refunds, retries transient failures up to three times, persists a `RefundTransaction` record, and emits success/failure events for downstream processing.

### Phase 1 – Design & Contracts

1. **Data Model** (`data-model.md`)
	- `RefundTransaction` entity (MongoDB collection) with fields: TransactionId (GUID), OrderId, Amount, CustomerWalletId, Status (Pending/Completed/Failed), CreatedAt, UpdatedAt, RetryCount.
	- Update `Order` aggregate (if needed) to expose `CustomerWalletId`.
2. **Contracts** (`contracts/`)
	- `RefundPixTransferCompletedEvent` (contains TransactionId, OrderId, Amount, CustomerWalletId, Timestamp).
	- `RefundPixTransferFailedEvent` (contains TransactionId, OrderId, ErrorDetails, RetryCount).
3. **Command**
	- `RefundPixTransferCommand` (properties: OrderId, RefundAmount, CustomerWalletId).
	- `RefundPixTransferCommandHandler` will:
	  * Validate WalletId format (UUID).
	  * Call `PixTransferService.TransferAsync` with retry logic (exponential back‑off, max 3 attempts).
	  * Persist `RefundTransaction` status updates.
	  * Emit appropriate event.
4. **Consumer Extension**
	- Extend `OrderCanceledPaymentRefundConsumer` to publish `RefundPixTransferCommand` after penalty calculation.
5. **Quickstart** (`quickstart.md`)
	- Steps to run the consumer locally, trigger a test `OrderCanceledPaymentRefundDomainEvent`, and verify MongoDB audit entry and emitted events.
